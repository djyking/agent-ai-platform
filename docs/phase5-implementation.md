## 4. 迁移与恢复边界

升级前必须停止新流量，完成可完成的 Run，并隔离旧集群。既有库迁移要求显式 `HARNESS_MIGRATION_OFFLINE_ACK=drained-isolated-cluster`；活跃 Run、held permit、近期 worker/槽位或指纹不匹配会拒绝迁移。变更配置还需审核旧指纹。平台 schema 升至 2，统计归属扩展由平台迁移回填，和核心状态/用量共用同一元数据行；新建 Run 在同一事务绑定归属。旧平台二进制拒绝新 schema，防止创建漏写统计归属的 Run。不能混跑第四/第五阶段 worker，也不能把旧二进制直接指向升级后的库当作回滚。

UNKNOWN 的 Run 和治理 permit 是不同账本：远端终止证据释放 permit，不会自动把 Run 改为成功；业务结果需要单独对账。强杀后 Run 状态和治理心跳通过独立事务收敛，过渡中的 DISPATCHED 仍占共享容量。

数据保留不是无人审核的定时删除。正文归档后 Run API/Studio 明示 `payloadArchived`，不再展示已过期正文，也不会因为重复创建请求重新执行。归档恢复、备份与密钥由部署方管理，不能只备份数据库而漏掉独立解密密钥。
