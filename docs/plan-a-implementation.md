## 4. 分阶段实施

### M1：工程与执行契约

建立可重复构建、开发文档、AgentDefinition、Run/Step 状态、模型/工具请求与结果、执行身份、预算、审批、持久化及事件接口。

先形成能独立运行的骨架和测试替身；不把 OpsAgent 中的业务字符串、固定目标、工单状态机带入核心。

### M2：受控运行闭环

实现默认有界 AgentLoop、模型与工具意图、执行结果提交、暂停/恢复/取消、精确审批、预算预留、错误分类和未知结果。

接入内部工具及 MCP 测试服务，共用日志、tracing、权限和调用控制；验证模型返回的原生 tool_call_id 与内部 invocationId 分别正确关联。

### M3：组合能力与示例

已实现版本化 Prompt 与上下文管理，同时实现轻量 Retriever 和有界 Workflow；二者通过共同运行协议使用模型、工具与审批，不各自再建执行账本。

### M4：验证与接入文档

验证故障恢复、精确审批、预算与权限、MCP 协议、配置版本及历史状态兼容；整理依赖接入方式、完整示例、限制与后续路线。

真实外部模型/MCP 联调与离线验证分别记录，不以模拟测试通过声称外部服务已验证。

## 5. 现在不阻塞启动的外部资料

先使用 ScriptedModel、FakeTool 和受控 MCP 测试服务构建、验证公共机制，不需要用户立即准备新账号。

真实联调前再提供/确定：

1. 一个真实模型的 provider、接口地址、模型名、凭据配置位置，以及允许的测试用量范围；如需复用 OpsAgent 配置，应明确允许复用的目标。
2. 一个真实 MCP server 的地址或启动方式、凭据位置、允许测试的工具与资源范围。
3. 如需真实 MySQL 联调，提供独立开发库的连接配置或指定可使用的现有开发库。

首次真实调用使用合成测试输入；需要使用实际业务资料时另按该资料的授权范围处理。凭据留在环境变量或不纳入 Git 的本地配置，不写进 prompt、审计正文和 trace。

网页登录授权可以用于任务所需的登录操作，但不替代对具体付费调用、测试目标及业务数据使用范围的确定。若遇必须用户本人完成的认证步骤，再说明具体阻塞，不预先要求额外权限。

## 6. 首版共同验收条件

- 同一个内核运行至少两个不同领域的示例。
- 内部工具与 MCP 工具经过同一权限、审批、预算、调用和观测链。
- 未批准、已拒绝、已过期或参数/契约发生变化的审批不能触发相应写工具。
- 意图先持久化；写后断连保留同一 invocation；无远端幂等保证的未知结果不自动重复执行。
- 暂停恢复不重置总额度和期限，不悄悄替换执行身份。
- 模型消息与工具返回配对正确，错误和用量未知有结构化表达。
- 已创建 Run 的 Prompt/模型配置基线不被新版本静默覆盖；当前撤权仍生效。
- 持久状态有兼容版本；SDK 升级后对旧状态按兼容、迁移或明确拒绝策略处理。
- 日志、事件、trace 可串联执行过程，并避免写入凭据。
- 若启用 RAG/Workflow，未启用这些模块的 Agent 仍可独立运行。

## 7. 实施结果和下一步

- 已实现 core、storage-jdbc、adapters、capabilities、examples 五个模块，Java 17 + Maven Wrapper 可独立构建。
- 默认 AgentProgram 与 Workflow 使用同一个运行内核和账本；内部工具、MCP、RAG 共用工具执行协议。
- 已提供 SQL 状态/事件事务、租约/fence、精确审批、用量结算、未知结果对账、跨线程 tracing 及可运行示例。
- 本地持久化使用 H2 验证；MySQL adapter 和建表脚本已提供，真实 MySQL 仍需独立开发库验证。
- 模型默认示例使用脚本模型，外部协议使用本机 HTTP/MCP fixtures 验证；真实服务资料到联调时再补充。
- 当前没有修改 OpsAgent、提交/推送远端或发布公共制品。后续先做 OpsAgent adapter 接入，再依据多业务共同需求决定中台服务化。
- 实际限制与接口语义见 [架构说明](architecture.md)，不将待建设的管理能力计作已经实现。
