# Stage four Studio integration contract

Implemented contract; endpoints are under `/v1/projects/{project}/studio`. The console BFF proxies the same paths. Existing authentication, CSRF, and project authorization apply. The [delivery record](phase4-implementation.md) defines the verified scope and remaining extensions.

All mutations require `If-Match: "sN"` and an `Idempotency-Key`. Creation uses `"s0"`. Every mutation returns an application document, with updated `revision` and ETag, including relevant `lastTask`, `lastExperiment`, or `publishedVersions`. Unknown network outcomes block dependent writes. `GET /commands/{key}` retrieves `{status:"COMPLETED",resourceId,operation,response}` for the exact requesting project/application/subject; 404 is not proof an in-flight write cannot still commit.

## Application

Editable body:

```json
{
  "name":"Research assistant",
  "templateId":"research",
  "instructions":"Answer from available evidence and include sources.",
  "modelProfileId":"trusted-profile-id",
  "knowledgeId":"",
  "toolIds":[],
  "outputFormat":"markdown",
  "requireReview":false,
  "approvers":[],
  "limits":{"maxTokens":12000,"maxModelCalls":4,"maxToolCalls":8,"maxSteps":60,"lifetimeSeconds":1800},
  "samples":[{"id":"sample-1","name":"Basic question","input":{"question":"Compare the documents"},"expectedContains":["source"]}]
}
```

Templates: `knowledge`, `research`, `structured`. All use a `question` input in the first stable contract. `structured` additionally accepts optional `fields` object, edited as key/value inputs, not raw JSON. `instructions` can use natural text; template variables are generated by the service. Tools are selected from approved descriptors. `approvers` contains exact application/subject assignments only for explicitly enabled human review.

Read document adds `id`, `revision`, `draftDigest`, `updatedAt`, `publishedVersions`, `defaultVersion`, `disabled`, `lastTask?`, `lastExperiment?`. Published version: `{version,releaseRef,draftDigest,publishedAt}`. Task link: `{id,runId,sessionId,applicationId,mode,snapshotId}`. `mode` is `PREVIEW`, `RELEASE`, or `EVALUATION`.

## Endpoints

| Method | Path | Body/result |
|---|---|---|
| GET | /templates | `{items:[{id,name,description,defaultDraft}]}` |
| GET | /capabilities | `{models:[{id,provider,model,...}],tools:[{id,key,modelName,inputSchema,...}],knowledge:[{id,name,visibility,...}]}` |
| GET | /applications | `{items:[Application]}` |
| GET/PUT | /applications/{id} | application / editable body |
| POST | /applications/{id}/preview | `{input:{question,fields?},sessionId?}`; persists immutable snapshot, creates real Run |
| POST | /applications/{id}/evaluate | `{}`; creates candidate and optional published-baseline real Runs for frozen samples; no write tools; human checkpoints remain real waits that must be explicitly resolved |
| POST | /applications/{id}/publish | `{reviewConfirmed:true,evaluationId}`; exact draft/configuration/knowledge bindings must match completed passing experiment; manual review recorded |
| POST | /applications/{id}/run | `{input:{question,fields?},sessionId?}`; starts the published default version |
| POST | /applications/{id}/default | `{version}`; changes only new runs |
| POST | /applications/{id}/disable | `{disabled}`; blocks new runs, existing run snapshots remain |
| GET | /experiments/{id} | live projected experiment: `{id,applicationId,draftDigest,status,passed,rows:[{sampleId,name,input?,expectedContains?,candidate:TaskResult,baseline?:TaskResult}],contract}`; current source authorization may omit sample input and expected text |
| GET | /tasks?applicationId=... | owner-visible tasks `{items:[Task]}` |
| GET | /tasks/{id} | Task + `run` (existing Run DTO), `artifacts` and `input` where currently authorized |
| GET | /tasks/{id}/artifacts/{artifactId} | authorized text/markdown attachment; current output authorization rechecked |
| GET | /commands/{key} | exact request receipt; no automatic replay |

`TaskResult` includes `{taskId,runId,status,output?,visibility,usage,passed?,reason?}`. Overall experiment status is `RUNNING`, `COMPLETED`, or `NEEDS_ATTENTION`; uncertain calls and failed/expired/denied Runs never count as passing. Output omission fails closed. `contract` reports separate deterministic workflow/template validation; it is not a model-quality score.

Task control/approval/events/trace use the existing Run routes, exact run ETags and approval digests. Tasks and sessions are durable product associations around those Runs. Artifacts are separately identified, content-addressed text/markdown exports of authorized completed output, with source Run and policy; they never claim to be arbitrary filesystem tools.

Shared knowledge and connection lifecycle endpoints live under `/knowledge` and `/capabilities` respectively; their service contracts are maintained alongside the implementing classes. The Studio exposes available choices, and never accepts model endpoints or secrets in application drafts.
