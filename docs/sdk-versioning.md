# SDK、制品与运行状态版本契约

日期：2026-09-15。适用范围：阶段 1 的 Harness SDK 和后续阶段 2 执行 API。

本文定义后续发布和接入规则，不表示已发布正式制品、实现自动状态迁移或部署平台 API。当前构建版本为 `io.github.djyking:agent-ai-platform:0.1.0-SNAPSHOT`；真实验证范围以 [首版验证记录](verification.md)、[阶段 1 进展与验证记录](phase1-progress.md) 和每次发布附带的实际报告为准。未取得的真实模型/MCP/MySQL 验收不能勾选通过。

## 1. SDK 版本与兼容承诺

SDK 使用 `MAJOR.MINOR.PATCH`；`0.x` 表示契约尚在稳定期，不承诺跨 minor 自动兼容，但不能将其解释为可无记录破坏业务。

| 版本变更 | 规则 | 接入方动作 |
|---|---|---|
| `0.1.z → 0.1.(z+1)` | 只做保持公开源码、二进制、持久语义和默认执行行为兼容的修复；必须给出回归证据 | 在相同配置和旧状态回归后升级 |
| `0.1.z → 0.2.0` | 新能力或任何破坏变更；变更说明列出 API、状态、配置、依赖和行为差异，不承诺直接恢复旧 Run | 固定版本评估，按兼容矩阵选择旧 Run 收尾或显式迁移 |
| `1.0.0` 以后 | major 承载破坏变更；minor 为已证明兼容的新增；patch 为兼容修复 | 不因 SemVer 兼容就跳过状态/故障回归 |
| `-SNAPSHOT` | 仅供开发集成，可能变化，不作为生产部署、审批或回滚的唯一标识 | 测试报告额外绑定 Git commit/工作区状态、构建时间、制品 SHA-256 |

当前所有 `harness-*` SDK 模块采用同一发布版本。接入方固定具体版本，禁止使用版本区间、`LATEST` 或动态替换运行中的 classpath；核心、存储、适配器、能力包应按同一组已验收版本升级。`harness-evals` 是离线验证工具，不需要作为业务生产依赖。后续模块若独立发布，必须先补模块依赖兼容矩阵。

以下都按**破坏变更**处理，即使 Java 方法签名没改：

- 删除/重命名公开类型、record 构造参数或枚举值，改变返回值或新增必须处理的状态；给公开接口增加抽象方法。
- 修改序列化字段类型、必填性、hash 规范化、action/invocation 身份生成、审批摘要、幂等作用域或错误语义。
- 改变默认权限、工具调用/审批策略、写操作重试条件、UNKNOWN 处理、预算结算或恢复行为。
- 让同一模型/Prompt/Workflow 版本生成不同冻结请求，或者使原合法配置失效。
- 改变 Program memory、节点推进、结果消费、SQL 事务/租约语义，即使版本字段仍然相同。
- 升级 JDK 下限或让既有公开类型发生不兼容的依赖变化。新增依赖本身不是自动兼容证明。

新增可选字段、默认接口方法、枚举值或日志字段也必须逐项验证：record 构造器、严格 JSON 消费者、穷尽 switch、hash 和反序列化可能受到影响。无法证明兼容时按 minor 升级并明确接入动作。需要紧急收紧安全行为时，发布说明直接标为有行为变化的升级；不得在 patch 名义下静默改变已审批操作。

## 2. 制品不可覆盖与发布标识

正式 `groupId:artifactId:version` 一经发布，其 JAR、POM、源码包及校验和不得替换。发现错误发布新版本，并停止推荐有问题版本；同一坐标不能指向不同字节。禁止重新打相同版本来“修补”已安装客户端。

SNAPSHOT 可在开发机更新，但不进入正式部署基线。正式发布应具备不可变 Git tag、完整依赖版本、JDK/Maven 版本、每个制品 SHA-256、兼容矩阵、变更说明和验证报告。tag 对应工作区必须干净；若当前未提交工作区生成了候选报告，报告应如实记录，不能伪装成已发布 tag 的证据。

当前 `mvn install` 只安装本机 Maven 仓库，不能称为私服或公网发布。制品仓库、访问范围和许可证尚未决定；本契约不触发公网发布、Git 推送、凭据创建或 CI secret 配置。选定发布渠道后再将不可覆盖规则落实到仓库策略。

## 3. 版本是多个独立维度

不能只看 Maven 版本就判断是否可以接管旧 Run。接管前必须同时满足下表以及实际旧快照回归。

| 维度 | 当前值/来源 | 当前检查与责任 |
|---|---|---|
| SDK artifact | `0.1.0-SNAPSHOT` | 开发坐标；当前没有正式 release |
| SQL schema | `harness_schema` 的 `run-store=1` | `JdbcRunStore` 检查已存在 schema；未知版本拒绝；没有自动 DDL 迁移器 |
| Run wire schema | `RunState.schemaVersion=1` | RunStore/StateGuards 拒绝其他值；不能手工改回 `1` 绕过检查 |
| Runtime 语义 | `RunState.runtimeVersion="1"` | 只接受 `1`；它与 Maven `0.1.0` 不是同一个版本轴 |
| Program 类型与业务定义 | `ProgramDefinition.program/id/version/spec` | 创建时冻结；宿主通过 program key 注册实现。当前没有按 definition.version 自动选择旧实现的调度器 |
| Workflow 状态 | memory 内 `schemaVersion=1` 与 spec fingerprint | Workflow 校验状态版本和冻结配置摘要；节点语义变更仍需单独证明旧 memory 可消费 |
| Prompt 版本 | `PromptTemplate.id/version` 与 fingerprint、输入快照 | 有效模板/输入固定；不得覆盖已发布同版本内容 |
| 工具契约 | key、version、完整 descriptor digest | 执行前比较冻结与当前契约；变化时拒绝旧动作，不自动替换工具或沿用旧审批 |
| 模型配置 | 冻结 ModelProfile/provider/model/parameters | 不能静默切换旧 Run 的模型；供应商复用别名后服务行为变化仍需外部实测 |
| 数据集与回放 | dataset id、schemaVersion、fingerprint、scope | 输入/预期变化必须更新可追溯版本；回放命中不代表新模型质量或外部服务可用 |
| 平台 API | `/v1` 与 OpenAPI 草案版本 | 独立于 SDK/状态版本；当前是设计，不是已运行服务 |

**当前可声明的候选兼容组合：**同一份经过验证的候选 SDK 构建，SQL 1 / Run schema 1 / runtime `1`，配合该构建中实际验收的 AgentProgram/WorkflowProgram 和冻结定义。不能据此声称任意未来 `0.1.x`、任意宿主 Program 或同名新实现都兼容。

宿主自定义 Program 必须记录实现版本与可恢复的定义版本集合；升级前提供包含已产生模型/工具结果、等待审批、UNKNOWN 和预算消耗的旧状态样本。当前注册表按 program key 查找实现，所以旧/新语义并存需使用独立 worker/注册表或经过测试的显式版本分派。禁止覆盖同名实现后让它无条件消费旧 memory。

## 4. 旧 Run 收尾、迁移与拒绝

默认采用**旧 Run 由兼容旧 worker 收尾，新 Run 采用新发布版本**。灰度或回滚调整新建请求路由；已经进入新账本的 Run 不能复制到旧执行器重新执行。

| 旧 Run 情况 | 升级时处理 |
|---|---|
| 已完成/取消/失败等历史记录 | 保持审计可读，必要时使用只读旧解码器；历史读取不授予重新执行权 |
| PREPARED 且版本兼容 | 用经过证明的兼容 worker 继续，重新检查当前权限、契约、审批和期限 |
| WAITING_INPUT / WAITING_APPROVAL / PAUSED | 保留原定义/输入、原摘要、预算和期限；不得借升级扩大额度或用新配置替换待审批请求 |
| IN_FLIGHT | 先确认旧执行者是否仍持有执行权；失联时按 UNKNOWN 处理，不能把阶段改回 PREPARED 直接重发 |
| UNKNOWN | 保留已发生副作用的可能性和对账归属；工具结果需独立核验，模型 UNKNOWN 保留预留，不伪造成功 |
| 无兼容 worker、状态版本未知或转换未验证 | 显式拒绝接管并保留记录，给出可审计原因；不能捕获解码错误后创建空 Run |

确需迁移活跃状态时，必须另立迁移任务：

1. 盘点 Run、版本、等待/未知状态和外部副作用，建立迁移前备份与可读验证。
2. 停止旧调度领取并完成执行权交接；不能仅复制数据库行。仍在远端执行的调用必须核验，不能通过改 fence 假定其撤销。
3. 用确定性的、可审计的转换器生成目标状态，保留 run/action/invocation 身份、已计数用量、原期限、审批绑定与已知回执；若必须改变身份或契约，单独设计协议，不靠字段替换。
4. 在隔离副本回放旧状态，检查结果消费、调用配对、UNKNOWN、预算及控制命令，然后对少量明确范围执行迁移。
5. 目标 worker 才取得执行归属；验证审计完整性，保留旧基线和迁移映射。任何回退先核验迁移后是否已产生新的外部副作用。

当前代码没有上述自动迁移协议。备份恢复同样不能直接重跑备份中的所有待执行项：备份时间点之后可能已发生真实写入。

## 5. 冻结配置与即时撤权并行生效

冻结对象包括运行身份归属、ProgramDefinition、Prompt/模型输入、工具契约、预算和总期限；其作用是让一次运行可解释、可恢复、可审批。它不冻结永不失效的权限。

当前生产宿主应提供动态 `AccessPolicy`，执行前查询现有授权；静态 `Actor.permissions` 只是本地/测试实现，不能单独实现即时撤权。RAG scope 同样从可信身份解析，并在返回检索结果前再次过滤。凭据通过 Secret Provider/回调按当前授权解析，不写入冻结输入。

发布新版本只影响新 Run。紧急禁用工具、撤销资源访问或凭据可以阻止旧 Run 的后续 dispatch；它不撤销已经发出的远端效果。权限、schema 或参数变化后不能沿用原审批，也不能为继续运行而自动放宽权限。已等待 Run 需要变更业务配置时，按新请求创建新 Run，并明确原 Run 的取消/收尾和未决副作用，不能原地改快照。

## 6. 影子验证与回放边界

回归用例首先使用合成或经过脱敏审查的数据。`harness-evals` 的 [离线基线与回放说明](../harness-evals/README.md) 记录了 fingerprint、scope、测试数据分类和负向断言。

`RecordedModel` / `RecordedTool` 没有真实调用 fallback：未命中拒绝，不能把“录制缺失”转换为在线访问。fingerprint 绑定 actor（包括项目、主体和权限）、node 与完整语义请求；排除 run/attempt/trace/deadline 等临时标识以允许跨 Run 对比。模型原生 tool_call_id 保留在消息中，按会话配对；同一 native ID 出现在不同 Run 不代表同一次业务执行，对外 invocation 身份仍由 Harness 使用 `runId:actionId` 隔离。

回放应在独立账本/数据目录和只有离线 adapter 的注册表中运行。不能把部分生产工具混入注册表，也不能将录制中的旧 receipt 用作当前真实 Run 的对账证据。回放 fixture 的 `REDACTED` 标记是人工审查声明，不会自动清除敏感数据或重新判断当前业务 ACL；调用链仍应走 Harness 和当前动态授权。

任何真实模型重跑都计入明确允许的用量；任何真实工具比较必须先固定单一执行归属。业务写操作不得新旧双路执行。需要对比写后结果时使用已经独立核验的录制结果，而不是再次向生产工具发送写请求。

## 7. 阶段 2 API 独立演进

阶段 2 对外 API 使用 `/v1`，OpenAPI 文档自身有草案/release 版本，见 [API 设计](phase2-api-design.md) 和 [契约验证说明](api/README.md)。Java SDK 的 Maven 版本、HTTP major、运行状态版本、Agent release 与资源版本互相独立；新增 SDK patch 不自动改变 HTTP `/v1`。

首个服务验收前允许调整草案，但必须更新 OpenAPI、契约样例和变更说明。对外冻结后，改变字段类型/必填性、权限范围、幂等作用域、错误/状态语义或审批/对账契约需要新 HTTP major，或明确的兼容过渡协议。不能用“只改实现”绕过客户端契约。

API 仅暴露经过授权的 DTO，不将 `RunState` 的 schema 直接当作 HTTP 格式。客户端 SDK 保持通信层职责；收到超时可用原幂等键恢复已接受命令的响应，不能自己重新执行 AgentLoop、刷新 Run 预算或为 UNKNOWN 写调用更换键重跑。

## 8. 发布与升级检查清单

每次发布在独立验证记录中写明下列实际结果和缺项。没有证据的项目标记“未验证/不适用及原因”，不得复制上一版通过结论。

- [ ] 版本、变更说明和各维兼容矩阵已更新；破坏变更有接入动作与旧 Run 处理办法。
- [ ] 固定 Git commit、干净工作区、JDK/Maven、依赖和制品 SHA-256；正式坐标/tag 未被使用。
- [ ] 全仓构建通过；记录命令、退出状态、测试数量、失败/跳过数与 Surefire 报告位置。
- [ ] 执行工程数据集 CLI；归档 JSON 报告与 dataset fingerprint，逐项预期通过。报告中的 synthetic token/本地耗时不作为模型质量、费用或 SLA。
- [ ] 对读取/恢复旧状态的组合跑回归：模型/工具原生配对、审批过期与撤权、重复请求、UNKNOWN、SQL 重开、预算/期限保持。
- [ ] 如涉及真实模型/MCP/MySQL 接入，记录端点类型、版本、隔离环境、允许操作和实际结果；凭据及业务正文不进入报告。未联调真实依赖时不得称为生产兼容发布。
- [ ] API 变化运行 OpenAPI 结构与正/负契约样例校验；仅草案通过不等于 HTTP 服务实现通过。
- [ ] 旧 worker 收尾/迁移/拒绝路线、回退仅影响新请求的规则和 UNKNOWN 对账责任均已确定。
- [ ] 制品渠道、许可证、访问范围和发布责任人已经确定；发布操作有明确范围，本地 install 不能代替发布验收。

已有历史基线为 [首版验证记录](verification.md)。本轮集成、真实依赖与 OpsAgent 身份桥的实际完成情况统一记录在 [阶段 1 进展与验证记录](phase1-progress.md)，其中引用实际 CLI artifact。本文件不重复预填通过数量，也不将尚待接入的真实业务身份链视为已完成。
