## VPS 前补充修复

- **Java HTTP 完整响应等待时限**：平台客户端、Ops 身份/引用/答案权限核验和 Ops RAG 的中台适配，对异步请求取得完整正文设置有界等待，超时或中断后取消未完成请求；不再只依赖请求头阶段的超时或对阻塞输入流逐次读取。响应正文大小限制仍生效，Ops 传输按实际字节数限制无 `Content-Length` 的分块响应。身份或权限响应不可用时拒绝放行；写请求超时仍保留结果未知语义，不自动重试、不跨执行器重放。
- **业务码严格校验**：客服身份、控制台登录、Ops 身份适配及答案权限核验拒绝超出 32 位有符号整数范围的业务码，避免数值截断后被误判为成功；小数、字符串等非整型值也不能通过。各接口保留原有成功约定，包括控制台省略 `code` 或整数 `0/200` 的兼容行为。验证码、会话有效期与身份体系未改变。
- **HARNESS 历史输出独立授权**：原实现将结果读取复用为执行委托，已完成 Run 在执行期限后也会被遮蔽，这是首版已声明限制。现在读取者仍须是原应用/项目/主体且有当前输出/检索权限，Auth 仍检查原 Run 绑定、明确撤销、账号/应用/grant、当前权限与原权限及角色上限；仅独立 `output-token` 路径允许执行期限自然到期。令牌固定为 `rag-output` audience，最长 120 秒且受访客有效期限制；新只读 RAG 路径继续核对冻结提示和全部当前来源 ACL。原委托不续期、不修改，执行和检索仍受原期限及 `rag` audience 约束，默认身份适配器不回退借用执行令牌。详见 [输出与幂等](platform-operations.md)。
- **观察证据与完成性**：失败样本落盘十个固定诊断字段（含阶段和白名单整数 errno/winerror），保留已收到的 HTTP 状态，不输出凭据、正文、键或异常文本；首次失败立即将 `qualityPassed` 置为 `false` 并保留 `firstQualityFailure`，后续成功窗口不能清除。`RUNNING` 只表示进程仍在执行。最终验收还检查完整分钟窗口、精确读写请求数和唯一写回执，截止时间前后均检查连续性；遥测失败和中断时保留实际部分窗口，不伪造服务健康状态。
- **模型传输诊断**：按完整 cause chain 识别固定的连接、DNS、TLS、超时、EOF、通道关闭、协议、正文过大及取消类别，优先保留具体类别并防止循环 cause；不输出原始异常文本、凭据或响应正文。分类补强不重放调用、不释放 UNKNOWN permit，也不能恢复旧调用已丢失的 throwable。
- **客服部署与入口路径**：保留默认 loopback 监听，允许通过受校验的配置显式指定容器监听地址；页面资源、验证码、登录和工作请求支持根路径、`/support/` 及嵌套路径前缀，拒绝跨源或含混资源基址。当前验证覆盖本机构建、静态部署契约和页面行为，不能代替目标 nginx/TLS 反向代理验收。

补充后的观察器 20 项隔离回归及独立审查已通过，其中模拟时钟和完整 24 小时证据用于验证防误判逻辑，不代表真实长跑通过。Java HTTP 修复与 Python 观察器是不同的传输实现；上述完整响应等待时限不外推为观察器已经具备总请求 deadline。详细记录格式、覆盖门槛及历史失败边界见 [连续观察说明](phase6-continuous-observation.md)。
