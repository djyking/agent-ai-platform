# 第五、六阶段收尾：中台与业务接入

本轮依据用户授权完成本机工程、OpsAgent 适配、联调及双仓库交付；VPS 部署、公网入口和目标环境验收留到用户指定的下一轮。两个仓库使用 `develop/harness-phase6`，不隐式合并 `main`，不覆盖原 OpsAgent 工作目录的其他未提交改动。

## 已实现能力

| 范围 | 行为与边界 |
| --- | --- |
| 独立控制台 | Studio 构建、同页体验、评测、发布、运行反馈；任务/反馈有签名游标和 SQL 索引，按应用、用户及快照边界分页 |
| 生成答案审核 | 模型先生成答案，再进入指定审核员的人审节点，批准后交付原答案；不把审批意见当答案，不因批准再次调用模型 |
| 现有身份 | 客服 BFF 复用 Ops 验证码、账号、会话和项目授权；每请求核验当前身份，浏览器不接触平台应用凭据或上游 JWT |
| 独立客服 | 正式发布发现、授权知识问答、用户隔离、人工审核、结果/事件与退出；验收资料是合成政策，不包含真实订单、退款或客户消息接口 |
| 受控接入 | 申请、审批/拒绝、固定权限档、离线写入现有身份源、候选部署配置、真实运行配置核验、轮换与停用；审批不直接签发凭据 |
| OpsAgent | `/api/rag/ask`、`/chat` 的知识问答可显式归属 HARNESS；平台承担模型执行与运行账本，Ops 保留检索、引用、业务权限、展示和请求归属 |
| 输出当前权限 | Ops 对完整提示、全部已供模型参考的来源、工单附件及用户/应用/项目/Run 绑定再次核验；撤权或来源变更后历史答案也不能继续读取 |
| 故障与回退 | 持久 LEGACY/HARNESS 归属、原请求键恢复、已有结果核对；失败不触发跨执行器降级，UNKNOWN 不重放；受控 PREPARING 恢复与保留清理分别有条件守卫 |
| ACP | 固定 ACP OpenAPI 0.2.0、官方 `acp-sdk==1.0.3` 的认证文本/JSON profile；复用 Run 账本，支持发现、同步/异步/事件流、人审恢复和取消 |
| 部署交付 | 双仓库 SHA、六个 JAR、Ops 前端、显式 SQL、平台部署/恢复/监控、客服 systemd/nginx 样例及逐文件摘要；私密配置不入包 |

Ops 原运维聚合领域、旧 AgentLoop 与会话 SSE 保留原业务语义。本轮迁移的是明确的知识问答链路，不声称所有旧运维执行器已经迁移或停用。ACP 上游已归档并转向 A2A；本实现不声称 A2A、ACP 会话或多媒体全兼容，详见 [ACP 契约](phase6-acp.md)。

## 验收证据

各项测试必须按实际制品 SHA 和执行范围记录，最终汇总见 [本轮验证清单](validation/phase6/README.md)。早期失败报告保留在本机忽略目录，不用最终通过覆盖排障历史。

已经获得的真实环境证据包括：

- MySQL + 现有 Ops Auth 的申请、审批、离线配置、生效核验、轮换与双侧停用；没有新建生产账号体系。
- Ops Auth → RAG → Knowledge/Ticket → 平台 → DeepSeek → 引用回答，以及同键去重、跨用户拒绝、撤权后答案遮蔽与显式 LEGACY 回退。
- 合成客服政策的真实 DeepSeek 评测，审核员来源 ACL 撤销后字段遮蔽、旧 ETag 拒绝，恢复权限后审核和发布。
- 官方 ACP SDK 的 DeepSeek → OpenAI 双 Agent 交接、事件流、用户隔离、审核恢复和取消。
- 在独立 MySQL 副本中执行真实 age 加密全量与 ROW binlog 恢复；核对全表摘要与排他 UTC 截止时间，不启动恢复实例中的应用 worker。
- 在独立升级库中用旧版本完成 Run，再离线升级、验证旧二进制拒绝 schema 2、新版本读取原结果及保留创建幂等关系。

本机连续观察由 [专用观察器](phase6-continuous-observation.md) 记录真实时长，只有经过至少 86,400 秒并满足完整性与质量门槛才算完成。短时压力不折算为 24 小时。第一轮 60 秒试跑无请求错误但尾延迟未达标；测量器当时每请求执行 Windows 系统代理探测，已为明确的 loopback 地址关闭代理并保留该失败记录。

最终源码完成 12 模块全量验证（369 项测试，零失败与跳过），最终制品完成客服三用户、官方 ACP SDK、Ops 原 Run 回读和升级重启检查。修正测量器后的 60 秒试跑为 600 次请求、零错误、P95 390 ms；独立 24 小时观察于 2026-10-20 19:17（UTC+8）启动，尚未完成。工程实现、短时联调和完整时间观察分别记录状态。

## 迁移和使用

Studio 和 Onboarding 索引采用 schema 2。迁移必须先排空并隔离旧集群，使用迁移账号；运行服务使用 DML 账号。活跃 Run、近期 worker、未决 permit、UNKNOWN 或配置指纹不符均不通过迁移。不能通过清空未知状态解除保护。

新 Human 节点的 `reviewContext` 默认关闭且 false 不序列化，保留旧发布摘要和原人输入节点语义。新 Studio 审核工作流才启用生成答案投影。参考 [人工审核](phase6-human-review.md)、[分页](phase6-studio-pagination.md)、[受控接入](phase6-onboarding.md)、[客服配置](../support-pilot/README.md)。

部署准备见 [双仓库工程包](phase6-bundle.md) 与 [阶段六部署组件](../deploy/platform/phase6/README.md)。本机账号与密钥仅保存在忽略目录 `.work/phase6/`，不随 Git 或 ZIP 上传。

## 下一轮 VPS 验收

下一轮确定主机、域名和现有身份源的连接方式后，执行 Linux 安装、TLS/可信代理、网络隔离、数据库与密钥备份、真实异机恢复、七天观察及公网访问。RPO ≤15 分钟、RTO ≤60 分钟与月度可用性是待实测目标，不能用本机数据库恢复耗时替代。

真实客户资料、订单/退款接口、客户消息渠道、向量索引托管、PDF/多媒体、工作流并行补偿与所有旧 Ops AgentLoop 的整体替换不是本轮已完成能力；接入这些业务时需另行明确数据、权限和验收范围。
